# ТЗ: Мобильные приложения «Домофон» (Android + iOS) + серверная платформа

Версия: 1.0 · Дата: 2026-06-11 · Статус: утверждено к разработке

Аналоги-референсы: Smartyard OEM (Гепард, `pro.tkgepard.smartyard_oem`), «Гепард Око» (iOS).

## 1. Цель проекта

Создать собственную платформу умного домофона: два нативных мобильных приложения
(Android, iOS) и серверную часть (API, SIP-телефония, медиа-сервер), позволяющие
жителям многоквартирных домов:

- принимать видеозвонки с подъездного домофона на смартфон;
- открывать дверь из приложения;
- смотреть подъездные/дворовые камеры в реальном времени и архив;
- видеть журнал событий (звонки, открытия, пропущенные);
- оплачивать ЖКУ и передавать показания счётчиков;
- общаться с управляющей компанией (чат, объявления).

Целевой рынок: Россия. Язык интерфейса: русский. Модель: B2B2C
(оператор/УК подключает дома, жители пользуются приложением).

## 2. Ключевые решения

| Область | Решение |
|---|---|
| Android | Kotlin 2.0, Jetpack Compose, Hilt, Retrofit/Moshi, Media3 (RTSP/HLS), WebRTC, Telecom ConnectionService, FCM |
| iOS | Swift 5.10+, SwiftUI, Alamofire, AVPlayer (HLS) + MobileVLCKit (RTSP), CallKit + PushKit (VoIP push), APNs |
| Backend | NestJS 10 (TypeScript), PostgreSQL 16, Redis 7, TypeORM, BullMQ, Socket.IO |
| SIP | Asterisk (PJSIP), мобильные клиенты — linphone-sdk / PJSIP |
| Медиа | MediaMTX: приём RTSP с камер/панелей, раздача HLS (архив/просмотр) и WebRTC (низкая задержка) |
| Хранилище | S3-совместимое (MinIO в dev), снапшоты и видеоархив |
| Push | FCM (Android, high-priority data), APNs + VoIP push через PushKit (iOS) |
| Авторизация | SMS OTP по номеру телефона (SMSC/SMS Aero), JWT access (15 мин) + refresh (30 дней) |
| Мин. версии ОС | Android 8.0 (API 26), iOS 16.0 |

## 3. Роли

- **Житель** — основной пользователь приложения; привязан к одной или нескольким квартирам.
- **Оператор/УК** — управляет домами, панелями, камерами, привязками квартир (через админ-API/панель, вне скоупа MVP мобильных приложений).
- **Гость** — вне MVP (этап 2: временные коды/QR).

## 4. Функциональные требования

### 4.1 Регистрация и вход
- Ввод телефона → SMS с 4-значным кодом (TTL 5 мин, повторная отправка через 60 с, максимум 5 попыток/час).
- После подтверждения: создание/поиск пользователя, выдача JWT-пары.
- Привязка к квартире: по лицевому счёту + коду подтверждения от УК, либо приглашением от уже привязанного жителя.
- Биометрия (Face ID/Touch ID/fingerprint) для быстрого входа; PIN-код как fallback.
- Несколько квартир/адресов на одном аккаунте; переключатель адреса.

### 4.2 Звонок с домофона (критический сценарий)
- Посетитель набирает квартиру на панели → Asterisk через бэкенд определяет устройства жителей → рассылает VoIP push (iOS PushKit) / data-push FCM (Android).
- iOS: CallKit-экран входящего звонка (включая фон/локскрин). Android: полноэкранный intent через ConnectionService/CallStyle-уведомление.
- До ответа показывается видеопревью с панели (snapshot или RTSP-поток).
- Ответ: двусторонняя аудиосвязь (SIP), одностороннее видео с панели.
- Кнопки: «Открыть дверь» (доступна и без ответа), «Ответить», «Отклонить», «Без звука».
- Параллельный звонок на несколько устройств одной квартиры; первый ответивший забирает звонок, остальным — отбой.
- Время от нажатия на панели до пуша ≤ 2 с; установление медиа после ответа ≤ 2 с.
- Если никто не ответил за 30 с — событие «пропущенный звонок» со снапшотом.

### 4.3 Открытие двери
- Из карточки домофона (главный экран), из экрана звонка, из уведомления.
- `POST /intercoms/{id}/open` → бэкенд → Asterisk/панель (SIP INFO или HTTP API панели).
- Подтверждение в UI ≤ 1.5 с; журналирование события «дверь открыта из приложения».

### 4.4 Камеры
- Список камер по адресам (подъездная панель + дворовые).
- Live-просмотр: WebRTC (задержка < 1 с) с fallback на HLS.
- Архив: HLS с таймлайном (хранение 7 дней по умолчанию, конфигурируемо), перемотка, скачивание фрагмента, скриншот в галерею.

### 4.5 Журнал событий
- Лента по квартире: звонки (отвечен/пропущен/открыто), открытия двери (ключ, приложение, код), системные события.
- Снапшот с камеры для каждого события; фильтры по типу и дате; пагинация.

### 4.6 ЖКХ
- Лицевые счета, текущие начисления, история платежей.
- Оплата: СБП и банковская карта через платёжный шлюз (ЮKassa — primary), Apple Pay недоступен в РФ — не делаем.
- Передача показаний счётчиков (вода/электричество/тепло) с историей.
- Квитанции PDF.

### 4.7 Чат и уведомления УК
- Чат жителя с диспетчером УК (Socket.IO/WebSocket, история, вложения-фото).
- Объявления УК (рассылки по дому/подъезду) — push + лента.

### 4.8 Настройки
- Профиль (имя, телефон), управление адресами.
- Режим «не беспокоить» (звонки идут, но без звука; расписание).
- Переадресация звонка на обычный телефонный номер (этап 2).
- Управление устройствами-сессиями, выход.

## 5. Нефункциональные требования

- **Надёжность доставки звонка**: ≥ 99% пушей доставлено за 2 с (при живой сети).
- **Безопасность**: TLS везде; SRTP для медиа; JWT в Keychain/EncryptedSharedPreferences; rate-limit OTP; защита `open` от replay (идемпотентность + аудит). Соответствие 152-ФЗ: ПДн хранятся в РФ.
- **Масштаб MVP**: 10 000 квартир, 1 000 одновременных стримов (горизонтальное масштабирование MediaMTX).
- **Наблюдаемость**: structured logs, Prometheus-метрики, Sentry в мобильных приложениях.
- **Офлайн**: приложение показывает кэш (адреса, журнал) без сети.

## 6. API (основные группы, REST `/api/v1`, OpenAPI/Swagger)

- `auth`: `POST /auth/otp/request`, `POST /auth/otp/verify`, `POST /auth/refresh`
- `users`: `GET/PATCH /users/me`
- `devices`: `POST /devices` (FCM/APNs/VoIP токены), `DELETE /devices/{id}`
- `apartments`: `GET /apartments`, `POST /apartments/link`
- `intercoms`: `GET /intercoms`, `POST /intercoms/{id}/open`
- `cameras`: `GET /cameras`, `GET /cameras/{id}/stream` (WebRTC/HLS URL + одноразовый токен), `GET /cameras/{id}/archive?from&to`
- `events`: `GET /events?apartmentId&type&cursor`
- `calls`: `GET /calls`, webhook от Asterisk: `POST /internal/calls/incoming`
- `billing`: `GET /billing/accounts`, `GET /billing/charges`, `POST /billing/payments`, `POST /billing/meters`
- `chat`: WebSocket `/ws/chat` + `GET /chat/messages`

## 7. Модель данных (основные сущности)

`users`, `apartments`, `user_apartments` (роль: owner/member), `buildings`,
`intercoms` (панель: SIP-параметры, URL открытия), `cameras` (RTSP-источник, флаг архива),
`devices` (push-токены по платформам), `calls`, `events`, `billing_accounts`,
`charges`, `payments`, `meter_readings`, `chat_messages`, `announcements`.

## 8. Этапы

### Спринт 0 — каркас (готово)
Моно-репо: backend-скелет (auth OTP + JWT, users, Swagger), docker-compose
(Postgres, Redis, MinIO, MediaMTX, Asterisk), Android- и iOS-каркасы со стабами
звонков и пушей.

### Спринт 1 — домен и авторизация
Сущности и миграции (apartments, buildings, intercoms, cameras, devices, events),
привязка квартиры, экраны входа по SMS и списка домофонов в обоих приложениях,
регистрация push-токенов.

### Спринт 2 — звонок и открытие двери
Asterisk-интеграция (webhook → push), SIP-клиенты (linphone-sdk), CallKit/ConnectionService
полный цикл, открытие двери, события звонков.

### Спринт 3 — камеры и журнал
MediaMTX-интеграция, live (WebRTC + HLS fallback), архив с таймлайном, журнал событий со снапшотами.

### Спринт 4 — ЖКХ и чат
ЮKassa, счета/показания, чат с УК, объявления, push-уведомления некритичных событий.

### Спринт 5 — стабилизация и публикация
Нагрузочное тестирование звонков, e2e-тесты, Sentry, RuStore + Google Play + App Store,
DDoS-защита, бэкапы.

## 9. Критерии приёмки MVP

1. Звонок с панели доставляется на оба устройства (Android локскрин, iOS CallKit) ≤ 2 с.
2. Видео с панели видно до ответа; после ответа — двусторонний звук.
3. Дверь открывается из приложения ≤ 1.5 с с записью в журнал.
4. Live-камера открывается ≤ 2 с, архив листается без зависаний.
5. Оплата ЖКУ проходит через СБП в sandbox ЮKassa.
6. Чат доставляет сообщения в обе стороны < 1 с при активном сокете.
7. Приложения проходят ревью Google Play и App Store.
