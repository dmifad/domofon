# Установка с нуля — пошаговое руководство для новичка

Это руководство рассчитано на человека, который **никогда не разворачивал**
серверы и не собирал мобильные приложения. Делайте всё по порядку, не пропуская
шаги. Каждую команду можно копировать целиком.

> Что в итоге получится: на сервере крутится backend и телефонный сервер
> (Asterisk). Домофон DNAKE S213 при нажатии кнопки звонит на ваш Android/iOS,
> вы отвечаете, видите видео и открываете дверь.

## 1. Что вам понадобится

**Оборудование (у вас уже есть):**
- Сервер — любой компьютер с Linux или Mac, который **всегда включён** и стоит в
  той же сети, что и домофон. Подойдёт мини-ПК, старый ноутбук, Raspberry Pi 4+.
- Домофон DNAKE S213, подключённый к той же сети (по кабелю или Wi-Fi).
- Android-телефон и/или iPhone для тестов.
- Wi-Fi роутер, к которому всё это подключено.

**Важное условие:** сервер, домофон и телефоны должны быть **в одной локальной
сети** (один роутер). Это обязательно для MVP.

**Программы, которые установим по ходу:**
- На сервер: Docker, Node.js, pnpm, git.
- Для Android: Android Studio (на ваш рабочий компьютер — Windows/Mac/Linux).
- Для iOS: Mac с Xcode (без Mac собрать iOS-приложение невозможно).

## 2. Словарик терминов

| Термин | Простыми словами |
|---|---|
| **Backend** | Программа-сервер: хранит пользователей, командует «открыть дверь», раздаёт настройки приложениям. |
| **Asterisk** | Телефонная станция. Через неё домофон «звонит» на телефоны. |
| **SIP** | Протокол интернет-телефонии. На нём работает звонок домофон→телефон. |
| **RTSP** | Протокол видеопотока с камеры. По нему телефон смотрит видео с панели. |
| **Docker** | «Коробка», в которой запускается Asterisk без сложной ручной установки. |
| **IP-адрес** | Адрес устройства в сети, вида `192.168.1.10`. |
| **Терминал** | Чёрное окно, куда вводят команды. На Mac — программа «Терминал», на Linux — «Terminal». |
| **APK** | Файл установки Android-приложения. |

## 3. Узнаём IP-адреса

Нам нужно знать два адреса. **Запишите их на бумагу** — они понадобятся много раз.

### IP сервера

На сервере откройте терминал и введите:

```bash
# Linux:
hostname -I | awk '{print $1}'
# Mac:
ipconfig getifaddr en0
```

Получите что-то вроде `192.168.1.10`. Это **IP сервера**.

### IP домофона

Самый простой способ — зайти в веб-интерфейс роутера (обычно `192.168.1.1` в
браузере, логин/пароль на наклейке роутера) и в списке подключённых устройств
найти DNAKE. Либо нажмите на самой панели сервисную комбинацию (см. инструкцию
DNAKE) — она покажет свой IP на экране.

Получите что-то вроде `192.168.1.50`. Это **IP домофона**.

> Дальше в руководстве я пишу `192.168.1.10` (сервер) и `192.168.1.50` (домофон).
> **Подставляйте свои числа.**

> 💡 Совет: чтобы адреса не менялись после перезагрузки, в настройках роутера
> закрепите их за сервером и домофоном (功能 называется «DHCP reservation» или
> «привязка по MAC»). Не обязательно для первого запуска, но избавит от проблем.

## Часть A. Backend на сервере

### A1. Устанавливаем программы

Откройте терминал на сервере.

**Ubuntu/Debian Linux:**

```bash
# Обновляем систему
sudo apt update

# Docker
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
# ВАЖНО: после этой команды выйдите из системы и зайдите снова (или перезагрузитесь),
# чтобы docker заработал без sudo.

# Node.js 22 (нужен ровно 22 или новее — в проекте используется встроенный SQLite)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs git

# pnpm (менеджер пакетов)
sudo npm install -g pnpm
```

**Mac:**

```bash
# Если нет Homebrew — установите с https://brew.sh, затем:
brew install node@22 git pnpm
brew install --cask docker
# Запустите Docker Desktop из Программ и дождитесь, пока кит в трее перестанет мигать.
```

Проверяем, что всё встало:

```bash
node --version    # должно быть v22.x.x или выше
pnpm --version    # любая версия
docker --version  # любая версия
git --version     # любая версия
```

Если все четыре команды показали версию — отлично, идём дальше.

### A2. Скачиваем код проекта

```bash
cd ~
git clone <URL-вашего-репозитория> domofon
cd domofon
```

> `<URL-вашего-репозитория>` — адрес с GitHub, например
> `https://github.com/dmifad/domofon.git`.

### A3. Настраиваем backend

```bash
cd ~/domofon/backend
cp .env.example .env
```

Теперь откройте файл `.env` текстовым редактором и поправьте под себя:

```bash
nano .env     # редактор в терминале. Сохранить: Ctrl+O, Enter. Выйти: Ctrl+X
```

Что менять (остальное пока не трогайте):

```ini
# IP вашего сервера (из шага 3)
SIP_DOMAIN=192.168.1.10

# Пользователь приложения: логин:PIN:sip-логин:sip-пароль
# Пароль придумайте свой и ЗАПОМНИТЕ — он же пойдёт в Asterisk на шаге B2.
USERS=demo:1234:user1:MoiSecret123

# Видео с панели. Пароль admin/admin — заводской у DNAKE, поменяйте если меняли.
# IP — вашего домофона (из шага 3).
INTERCOM_RTSP_URL=rtsp://admin:admin@192.168.1.50:554/0

# Открытие двери по HTTP (если панель умеет; точный путь см. в шаге C4)
INTERCOM_OPEN_URL=http://192.168.1.50/cgi-bin/door_unlock
INTERCOM_OPEN_AUTH=admin:admin
```

Сохраните файл (`Ctrl+O`, `Enter`, `Ctrl+X`).

### A4. Запускаем backend

```bash
cd ~/domofon/backend
pnpm install      # скачает зависимости, идёт 1-2 минуты
pnpm start:dev
```

Если увидели строку вида `Domofon API on http://0.0.0.0:3000` — **backend
работает**. Не закрывайте это окно терминала.

### A5. Проверяем backend

Откройте **второе** окно терминала и введите (подставьте свой IP сервера):

```bash
curl -X POST http://192.168.1.10:3000/api/v1/auth/login \
  -H 'content-type: application/json' \
  -d '{"username":"demo","pin":"1234"}'
```

Должны увидеть ответ вроде:

```json
{"token":"abc123...","userId":"demo","sip":{"domain":"192.168.1.10","username":"user1","password":"MoiSecret123"}}
```

Видите `token` и `sip` — **backend настроен правильно**. Переходим к Asterisk.

> ❗ Если `sip` равен `null` — в `.env` в строке `USERS` должно быть **четыре**
> части через двоеточие (`demo:1234:user1:MoiSecret123`), а `SIP_DOMAIN` не пустой.
> Поправьте, остановите backend (`Ctrl+C`) и снова `pnpm start:dev`.

## Часть B. Asterisk (телефонный сервер)

### B1. Прописываем пароли

```bash
cd ~/domofon/infra/asterisk
nano pjsip.conf
```

Найдите две строки и замените заглушки на пароли:

```ini
password=<PANEL_PASS>      # → пароль для домофона, например password=PanelSecret123
...
password=<MOBILE_PASS>     # → ТОТ ЖЕ пароль, что в USERS (.env), т.е. password=MoiSecret123
```

> `<MOBILE_PASS>` обязан совпадать с sip-паролем из `USERS` в `.env`
> (в нашем примере `MoiSecret123`). `<PANEL_PASS>` — отдельный, его вы введёте
> в домофон на шаге C2.

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`).

### B2. Правим адрес backend для Asterisk

```bash
nano extensions.conf
```

В самом верху найдите блок `[globals]` и строку `BACKEND_URL`. Поскольку Asterisk
запускается в режиме «host network», на **Linux** правильно так:

```ini
BACKEND_URL=http://127.0.0.1:3000/api/v1
```

На **Mac (Docker Desktop)** оставьте:

```ini
BACKEND_URL=http://host.docker.internal:3000/api/v1
```

Сохраните.

### B3. Запускаем Asterisk

```bash
cd ~/domofon/infra
docker compose up -d
```

Первый запуск качает образ — подождите минуту. Проверяем, что контейнер живёт:

```bash
docker compose ps
```

В колонке STATUS должно быть `Up` (или `running`).

### B4. Проверяем, что Asterisk видит настройки

```bash
docker exec -it $(docker ps -qf name=asterisk) asterisk -rx "pjsip show endpoints"
```

Должны увидеть в списке `panel1` и `user1`. Пока они в статусе `Unavailable` —
это **нормально**, потому что ни домофон, ни телефон ещё не подключились.

## Часть C. Настройка домофона DNAKE S213

### C1. Заходим в веб-интерфейс панели

В браузере на компьютере (он должен быть в той же сети) откройте:

```
http://192.168.1.50
```

(адрес домофона из шага 3). Логин/пароль по умолчанию обычно `admin` / `admin`.

### C2. Прописываем SIP-аккаунт

Найдите раздел **SIP** (может называться «SIP Account», «VoIP» или
«Network → SIP»). Заполните:

| Поле | Значение |
|---|---|
| SIP Server / Proxy | `192.168.1.10` (IP сервера) |
| Server Port | `5060` |
| Username / Account | `panel1` |
| Password | `PanelSecret123` (тот, что в `pjsip.conf` для `<PANEL_PASS>`) |
| Enable / Register | включить (On) |

Сохраните настройки панели.

### C3. Прописываем, кому звонить

Найдите раздел **Phonebook** / **Call** / «Кнопка вызова». Настройте, чтобы
кнопка вызова набирала номер `101`. (В нашем диалплане любой номер с панели
переадресуется на телефоны, но проще задать `101`.)

### C4. Включаем видео и DTMF-открытие

- **Видео:** раздел Camera/Video → RTSP включить (On). Запомните формат RTSP-URL.
  Проверить можно на компьютере программой VLC: «Медиа → Открыть URL» →
  `rtsp://admin:admin@192.168.1.50:554/0`. Если видео пошло — этот URL и есть
  `INTERCOM_RTSP_URL` в `.env`.
- **Открытие двери в звонке:** раздел Door/Intercom → «DTMF Unlock Code» = `#`,
  «DTMF Type» = `RFC2833`.

### C5. Проверяем, что панель зарегистрировалась

На сервере:

```bash
docker exec -it $(docker ps -qf name=asterisk) asterisk -rx "pjsip show contacts"
```

Должна появиться строка с `panel1` и статусом `Avail`. **Это значит — домофон
подключился к вашему серверу.** 🎉

> ❗ Если не появилась — на сервере включите подробный лог и нажмите на панели
> «сохранить SIP» ещё раз:
> ```bash
> docker exec -it $(docker ps -qf name=asterisk) asterisk -rx "pjsip set logger on"
> docker logs -f $(docker ps -qf name=asterisk)
> ```
> Частые причины: неверный пароль (ошибка 401 в логах), неверный IP сервера в
> панели, разные подсети.

## Часть D. Android-приложение

Собирать APK будем на вашем **рабочем компьютере** (не обязательно на сервере).

### D1. Устанавливаем Android Studio

1. Скачайте с https://developer.android.com/studio и установите
   (Windows/Mac/Linux).
2. При первом запуске согласитесь скачать «Android SDK» — мастер сделает это сам.

### D2. Открываем проект

1. В Android Studio: **File → Open** → выберите папку `domofon/mobile/android`.
2. Дождитесь, пока внизу пройдёт надпись «Gradle sync» (несколько минут в первый
   раз — качаются зависимости).

### D3. Собираем APK с адресом вашего сервера

Откройте встроенный терминал в Android Studio (**View → Tool Windows → Terminal**)
и введите (подставьте IP сервера):

```bash
# Mac/Linux:
./gradlew :app:assembleDebug -PapiBase=http://192.168.1.10:3000
# Windows:
gradlew.bat :app:assembleDebug -PapiBase=http://192.168.1.10:3000
```

Готовый файл появится тут:
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`

### D4. Устанавливаем на телефон

**Способ 1 (просто):** перекиньте файл `app-debug.apk` на телефон (через USB,
мессенджер, облако) и откройте его на телефоне. Разрешите «установку из
неизвестных источников», когда телефон попросит.

**Способ 2 (через USB-отладку):** включите на телефоне «Режим разработчика» и
«Отладка по USB», подключите кабелем и в терминале Android Studio:

```bash
./gradlew :app:installDebug -PapiBase=http://192.168.1.10:3000
```

### D5. Первый вход

1. Откройте приложение «Домофон» на телефоне.
2. Разрешите доступ к **микрофону** и **уведомлениям** (иначе звонок не сработает).
3. Войдите: логин `demo`, PIN `1234`.
4. На главном экране должна появиться надпись **«SIP: на связи ✓»** и
   видео-превью с панели.

Проверим со стороны сервера, что телефон подключился:

```bash
docker exec -it $(docker ps -qf name=asterisk) asterisk -rx "pjsip show contacts"
```

Теперь должно быть **два** контакта: `panel1` и `user1`. 🎉

## Часть E. iOS-приложение

> ⚠️ Для сборки iOS-приложения **обязателен Mac**. На Windows/Linux это
> невозможно — таково ограничение Apple.

### E1. Устанавливаем инструменты

```bash
# Xcode — из App Store (большой, качается долго). После установки один раз:
sudo xcodebuild -license accept

# XcodeGen — генерирует проект Xcode из нашего описания
brew install xcodegen
```

### E2. Генерируем проект и открываем

```bash
cd ~/domofon/mobile/ios
xcodegen generate
open Domofon.xcodeproj
```

Xcode откроется и сам докачает пакеты (KeychainAccess, Socket.IO, VLCKit) —
подождите, пока вверху перестанет крутиться индикатор.

### E3. Подписываем приложение

Чтобы запустить на реальном iPhone, нужна бесплатная подпись:

1. В Xcode слева кликните на синюю иконку «Domofon» (самый верх дерева файлов).
2. Вкладка **Signing & Capabilities**.
3. Поставьте галочку **Automatically manage signing**.
4. В поле **Team** выберите ваш Apple ID (Add Account → войдите своим Apple ID,
   бесплатного достаточно).

### E4. Запускаем на iPhone

1. Подключите iPhone к Mac кабелем, разблокируйте, нажмите «Доверять».
2. Вверху Xcode рядом с кнопкой ▶ выберите свой iPhone из списка устройств.
3. Нажмите ▶ (Run).
4. На iPhone первый раз: **Настройки → Основные → VPN и управление устройством →
   ваш Apple ID → Доверять**.

### E5. Первый вход

1. Откройте приложение, разрешите микрофон.
2. В поле «URL backend» введите: `http://192.168.1.10:3000/api/v1`
3. Логин `demo`, PIN `1234`.
4. Увидите список домофонов и видео с панели.

> Что работает на iOS сейчас: вход, список панелей, видео (RTSP), открытие двери,
> показ экрана входящего звонка. **Звук в звонке** на iOS пока в разработке
> (нужна интеграция библиотеки linphonesw) — см. `docs/TESTING.md`, этап 10.

## Часть F. Первый звонок

Когда всё настроено, проверьте «вживую».

**Сначала — тест без панели** (чтобы убедиться, что цепочка сервер→телефон жива).
На сервере:

```bash
docker exec -it $(docker ps -qf name=asterisk) \
  asterisk -rx 'channel originate PJSIP/user1 application Playback hello-world'
```

На Android должен появиться полноэкранный входящий звонок. Ответьте — услышите
«hello world». **Если это работает — самое сложное позади.**

**Теперь настоящий звонок:** нажмите кнопку вызова на домофоне DNAKE.

Должно произойти:
1. Телефон зазвонит (полный экран входящего).
2. Нажимаете «Ответить» — слышите и говорите с тем, кто у панели.
3. Видите видео с камеры панели.
4. Кнопка «Открыть дверь» — замок щёлкает.

Если на каком-то шаге сбой — откройте `docs/TESTING.md`, там этап 8 с таблицей
«что где смотреть» для каждого шага звонка.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `curl` на шаге A5 не отвечает | Backend запущен? (`pnpm start:dev` в окне не закрыто). Правильный ли IP сервера? |
| `sip: null` в ответе логина | В `.env` строка `USERS` должна иметь 4 части через `:`, `SIP_DOMAIN` не пустой. Перезапустить backend. |
| Панель не в `pjsip show contacts` | Пароль в панели ≠ пароль в `pjsip.conf`. Включить `pjsip set logger on` и смотреть лог. |
| Телефон: «SIP: ошибка» | Пароль в `pjsip.conf` `[user1]` ≠ паролю в `USERS`. Сервер и телефон в одной сети? |
| Звонок идёт, но звук в одну сторону | Это NAT/RTP. Убедитесь, что Asterisk в режиме `network_mode: host` (так в нашем compose) и сервер с телефоном в одной сети. |
| Нет видео в звонке | В панели включить «SIP Video». В `pjsip.conf` у обоих endpoint есть `allow=h264` (уже стоит). |
| Дверь не открывается по `#` | В панели «DTMF Type» = `RFC2833`, «DTMF Unlock Code» = `#`. |
| Звонок не будит закрытое приложение (Android) | Это нормально для MVP без Firebase. Пока держите приложение открытым. Настройка Firebase — в `docs/TESTING.md`, этап 11. |

### Полезные команды диагностики

```bash
# Логи backend — видны прямо в окне, где запущен pnpm start:dev

# Логи Asterisk
docker logs -f $(docker ps -qf name=asterisk)

# Кто сейчас подключён к Asterisk
docker exec -it $(docker ps -qf name=asterisk) asterisk -rx "pjsip show contacts"

# Перезапустить Asterisk после правки конфигов
cd ~/domofon/infra && docker compose restart asterisk
```
